---
title: Adding a provider
description: Ship another hosted product on top of the Postgres driver
---

Hosted Postgres products reuse `@db-sdk/postgres`. Supabase in `@db-sdk/supabase` is the reference.

## Package

Publish `@db-sdk/<product>`. Depend on `@db-sdk/postgres` and `db-sdk`. Put product auth and listing APIs in that package when the flow is reusable across hosts.

## Resolve

Turn product credentials into a Postgres URI, or into host, user, password, and database. That resolve step is the provider’s job.

## Open

Call `postgres({ id: "<product>", connectionString })`. Do not reimplement SQL policy or catalog. Export `id` as the product name and keep `driver` as `"postgres"` so hosts can reuse one SQL tool for every Postgres-backed connection.

## Example

A Neon-shaped provider looks like this:

```ts
import { postgres } from "@db-sdk/postgres";
import type { DatabaseProvider } from "db-sdk";
import type { PostgresQuery } from "@db-sdk/postgres";

export async function neon(options: {
  apiKey: string;
  projectId: string;
}): Promise<DatabaseProvider<PostgresQuery>> {
  const connectionString = await resolveNeonConnectionString(options);

  return postgres({
    id: "neon",
    connectionString,
  });
}
```

Raw URI users skip the hosted package and call `postgres({ connectionString })` directly.

See [ADR 0003](https://github.com/becausify/db-sdk/blob/main/docs/decisions/0003-providers-and-drivers.md), [Postgres](/docs/postgres), and [Supabase](/docs/supabase).
