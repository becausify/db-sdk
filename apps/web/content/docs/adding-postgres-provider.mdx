---
title: Adding a Postgres provider
description: Checklist for a second hosted provider on the Postgres driver (Neon-sized)
---

Hosted Postgres products reuse `@db-sdk/postgres`. Supabase is the reference implementation in `@db-sdk/supabase`.

## Checklist

1. Create `@db-sdk/<product>` that depends on `@db-sdk/postgres` and `db-sdk`.
2. Own product auth/API (OAuth, API keys, branch listing) in that package — not in the host if the flow is reusable.
3. Resolve a Postgres URI (or discrete host/user/password).
4. Call `postgres({ id: "<product>", connectionString })` — do **not** reimplement SQL policy or catalog.
5. Export `id: "<product>"` with `driver: "postgres"` so hosts can use one SQL tool for every Postgres-backed connection.

## Sketch (Neon)

```ts
import { postgres } from "@db-sdk/postgres";
import type { DatabaseProvider } from "db-sdk";
import type { PostgresQuery } from "@db-sdk/postgres";

export async function neon(options: {
  apiKey: string;
  projectId: string;
  // …product-specific resolve
}): Promise<DatabaseProvider<PostgresQuery>> {
  const connectionString = await resolveNeonConnectionString(options);

  return postgres({
    id: "neon",
    connectionString,
  });
}
```

Raw URI users skip the hosted package and call `postgres({ connectionString })` directly.

See [ADR 0003](https://github.com/becausify/db-sdk/blob/main/docs/decisions/0003-providers-and-drivers.md), [PostgreSQL driver](/docs/postgres), and [Supabase provider](/docs/supabase).
